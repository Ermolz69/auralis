An audit of the host found that every newly prepared run used a random run ID in its segment seed and a private cache directory. This prevented cross-run reuse even when only one cue changed. New plans now derive stable role and seed identities from the project and cue ID, and new runs use a shared project cache with the renderer's existing WAV/metadata verification. Runs that already have a private cache keep that path for resume. Model-free application tests confirmed that two distinct approved plans for the same cues retain the same role and seed keys; the real renderer's separate corruption and changed-text matrix passed above. Native cross-run reuse remains to be measured after qualification.

The native scenario is prepared to publish 13 runs. Its original ten cover two engines, two voices, text and subtitle plans, cancellation and crash resume. It then prepares the same long text in a new run and requires every checkpoint to be `cached`; stops the app, damages exactly one verified cache WAV inside the temporary project cache, resumes and requires only that segment to be `generated`; changes one phrase in another reviewed text and requires only its chunk to regenerate. It checks saved plan and manifest hashes, checkpoint origins, the restored cache file, final WAV hashes and durations, managed publication, playback, and unchanged results after another restart. Four model-free SQLite tests passed, including rejection of a corruption path outside the project cache and a wrong saved checkpoint origin. The installed VoxCPM2 split-policy gave six chunks for both exact native texts and changed only chunk 0; its text, profile, config, chunk and script hashes are saved in `tools/native-e2e/evidence/CACHE_SPLIT_20261021.json` (SHA-256 `9f1e28df3cf1102e0373aecab9485fbefa85e7c9499b9e5363f21290c0c0784d`). These checks prepare the native test but do not substitute for running it with qualified voices.

The native verifier also now reads `duration_ms` from the saved publication JSON and compares it with the WAV header. Previously it read that field from the SQLite row, where no such column exists, so the duration comparison could silently accept a mismatch. A synthetic managed WAV test proves that a changed saved duration is rejected; the verifier now retains each run's exact plan, profile/voice/model hashes, attempt timestamps and checkpoints, file hashes and independently computed duration.
