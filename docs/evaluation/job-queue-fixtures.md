# Job Queue Fixture Evidence

Scope: durable dispatch and the production subtitle-import application path.
This record uses local fixtures, SQLite and owned local test processes. It makes
no model, external-service, real-media or general-operation performance claim.

## Frozen comparison

Before running the comparison, `task rs:bench:queue` and its workload were added
to the Taskfile command documentation. Each of three repetitions uses 12 separate
projects and jobs, each with a cancellable 40 ms asynchronous local wait. The
sequential budget has one network unit; the parallel budget has two. CPU, disk and
process budgets are two each. Pending capacity is 1024; window and active slots are 64. Wall time includes SQLite project creation, admission, dispatch and terminal
persistence. Each repetition also measures a separate Running cancellation. The
executor records its actual peak concurrent useful work. No arbitrary timing sleep
is used as a correctness assertion in concurrent queue tests.

Raw output: `target/job-queue/fixture-comparison.json`, generated by the ignored,
explicitly requested benchmark test on Windows on 2026-10-10.

## Confirmed execution boundary

an executor-entry channel acknowledgement before cancellation timing, so a durable
Running row alone cannot stand in for useful work having begun. The initial

## Validation scope

Concurrent foreign Caster/TTS/Translate changes were present throughout this work.
They were preserved. Whole-workspace gates can therefore report unrelated failures;
the final record separates those failures from queue verification. Queue correctness
tests exercise actual SQLite transitions and the application runner, using channels,
activation acknowledgements, barriers and durable states.

The tests cover independent concurrency, exhaustion, bypass/fencing, invalid demands,
atomic overflow, cancellation/dispatch races, deletion, joined CPU work, initial and
terminal persistence faults, executor/start failure, unconfirmed process ownership,
import cleanup, exact Pending recovery, malformed descriptors and interrupted Running.
The Windows owned-process check launches and terminates a local child tree.
