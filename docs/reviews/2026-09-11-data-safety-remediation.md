# Data safety audit remediation

The subsequent review of `71cf1ad7` found gaps in the integration and lifecycle contracts below.
See [the follow-up](2026-09-11-remediation-follow-up.md) for their corrections and additional tests.
The verification table in this initial report describes the first implementation, not the follow-up.

This change addresses D01–D08 from the audit of commit
`7878e9df4d3db2090e791388cadd7989c315383e`. It does not implement the audit's unmeasured
performance hypotheses, backup/restore, a telemetry exporter, or new media pipeline stages.

## Implemented contracts

- **D01:** retain dead finalization intent for live pending artifacts. Two maintenance passes beyond
  retention preserve staging; an explicit, idempotent UI retry reuses existing bytes.
- **D02:** recovery persists job revision and finish time with the terminal snapshot, guarded by
  expected status and revision. Paired project/job writes remain atomic and replay-safe.
- **D03:** schema version 5 stores theme and pins in SQLite. Conditional legacy import cannot replace
  native state. Pin values and their migration marker commit atomically; browser cleanup follows
  acknowledgement and preserves avatars. UI distinguishes pending, saved, and failed writes.
  The app provider owns persistence; shared theme controls have no backend dependency.
  Writes within one window are ordered (per project for pins), so a delayed older read cannot
  cause an older choice to be committed after the latest choice.
- **D04:** an OS lease owns each canonical app root before startup recovery. Stale filenames do not
  block restart, while another process cannot recover the same root concurrently.
- **D05:** staging files are synchronized before the pending-artifact intent. Finalization checks a
  regular, non-symlink file and expected byte length when known; missing or mismatched bytes never
  become ready. Existing final files undergo the same checks. Files are synchronized before ready;
  Unix directory synchronization covers managed ancestor directories and the removed staging entry.
- **D06:** project DTOs expose revision; rename requires the revision observed by its caller.
  Stale rename returns conflict, reloads the list, and requires explicit retry. Selected projects,
  list results, and pinned-project projections reject lower-revision replacements.
- **D07:** command spans accept only UUID-shaped correlation headers generated by the typed UI
  boundary; command arguments are skipped. Async wrappers are instrumented. Outbox attempts carry
  the durable message ID and a changing attempt number. Terminal notifications get two bounded
  attempts per event, without changing an already committed business result. Open-project and
  transcript observers reread visible snapshots every 30 seconds and on focus, with one fallback
  request in flight and a one-second focus throttle. Global frontend error reporting is allowlisted
  and rate-limited; raw errors, stacks, paths, URLs, and request bodies are not forwarded.
- **D08:** diagnostics drop whole oversized events above 32 KiB; each sink queues at most 128 events.
  File output has a 16 MiB per-file and 30-file total budget; it never falls back to a full old file
  after rotation failure. Console output is lossy and nonblocking. Independent minute sampling
  reports drops and I/O failures without recursively using the failed file sink. Shutdown passes a
  remaining absolute budget through jobs, workers, and log flushing. Unconfirmed tasks retain
  resources; confirmed tasks whose mutation lock could not be acquired report deferred cleanup.

## Verification and limits

Regression tests cover disk-backed preference reopen and migration rollback, recovery CAS/replay,
dead retention and manual retry, invalid/truncated final files, root exclusion across processes,
stale UI writes/results, failed notification retry, event/file budgets, and blocked shutdown.
The frontend browser fixtures model the new IPC revision and preference contracts, but remain
test doubles, not evidence of native filesystem durability.

Run `task rs:test`, `task rs:test:storage`, `task rs:test:youtube`, `task rs:clippy`,
`task check:frontend`, and `task q:ipc-contract` for the corresponding regression gates.
Native acceptance remains a separate `task desktop:e2e:native` check.

The native runner above covers media/import/cancellation, not a power cut or native multi-window
preference restart. Preference durability is separately covered by disk-backed SQLite reopen tests
and frontend acknowledgement/migration tests. No CI run or release-platform certification is implied.

This change does **not** claim power-loss certification. Windows directory synchronization is not
provided by Rust's portable API here; device caches and filesystem semantics need a dedicated
power-failure test on each release platform. File length is not a content digest and cannot detect
same-length corruption. Existing oversized logs are not rewritten, and external writers to the
private log directory are outside the accounting contract. A write that partially fails can leave
one incomplete final record; subsequent records are suppressed until rotation.

Correlation is bounded local diagnosis, not exactly-once event delivery or a durable trace archive.
Retention/lossy logging can remove a pre-restart request link; the outbox message ID itself survives
retries. Periodic snapshots repair missed notifications while a visible observer remains mounted.
No telemetry is uploaded. Hard process/OS stalls and permanently blocked kernel I/O still require
process-level release testing; a timeout report does not certify that such a task stopped.
